🐉 Hydra — Online Password Cracking Tool

1. What is Hydra?

Hydra is a brute-force online password cracking program. It is a fast, parallelized login "hacking" tool used to test the strength of authentication systems by systematically attempting username/password combinations against a target service.

Hydra works by attempting many login combinations across many network protocols simultaneously (multi-threaded), making it much faster than manual or single-threaded attempts.
⚠️ Legal note: Hydra should only be used against systems you own or have explicit written authorization to test. Unauthorized access attempts are illegal in most jurisdictions.

3. Hydra Commands

3.1 SSH Brute Force

# Attempt SSH login using a username and password wordlisthydra -l <username> -P <full_path_to_wordlist> MACHINE_IP -t 4 ssh
FlagMeaning
-lSpecifies a single username
-PSpecifies the path to a password wordlist
-tSets the number of parallel threads/connections to spawn

3.2 POST Web Form (Generic Syntax)

# Generic syntax for brute-forcing a web login formsudo hydra <username> <wordlist> MACHINE_IP http-post-form "<path>:<login_credentials>:<invalid_response>"

Parameter breakdown:

ParameterMeaning
http-post-formTells Hydra the request type is HTTP POST
<path>The login page URL (relative path)
<login_credentials>Username/password fields, e.g. username=^USER^&password=^PASS^
-VVerbose output — shows every login attempt as it happens
<invalid_response>A unique string that appears on the page only when login fails (used to detect failure)

3.3 POST Login Form (Concrete Example)

# Brute-force a POST login form on the root page "/"hydra -l <username> -P <wordlist> MACHINE_IP http-post-form "/:username=^USER^&password=^PASS^:F=incorrect" -V

Explanation:

  • The login page is only /, i.e., the target's main/root IP address page.
  • username is the form field name where the username is entered.
  • The token ^USER^ is replaced by each specified username.
  • password is the form field name where the password is entered.
  • The token ^PASS^ is replaced by each password from the wordlist.
  • F=incorrect tells Hydra to treat the login as a failure whenever the string "incorrect" appears in the server's response.
  • -V gives verbose output, printing every attempt to the terminal.

3.4 Targeting a Non-Default Port

# Same attack, but specifying a custom port with -shydra -l <username> -P <wordlist> MACHINE_IP http-post-form "/:username=^USER^&password=^PASS^:F=incorrect" -s <port> -V
FlagMeaning
-sSpecifies a non-default port for the target service

7. Basic Hydra Syntax Structure

hydra [options] <target IP> <protocol/service>

General order of a Hydra command:

  1. hydra — the binary
  2. Login options (-l / -L)
  3. Password options (-p / -P)
  4. Optional tuning flags (-t, -s, -f, -V, etc.)
  5. Target (IP, hostname, or CIDR range)
  6. Protocol/service name (with any protocol-specific parameters, e.g. http-post-form)

8. Username & Password List Options

FlagDescription
-lSingle username
-LFile containing a list of usernames
-pSingle password
-PFile containing a list of passwords
-CColon-separated "login:password" combo file (replaces -l/-L and -p/-P)
-e nsrExtra checks: n = null password, s = login as password, r = reversed login as password
-xGenerate passwords via brute-force mask, e.g. -x 4:8:aA1 (min:max:charset)
-uLoop through users first, then passwords (helps avoid account lockouts)
# Using a combined login:password filehydra -C combo.txt MACHINE_IP ssh

8.1 Common Wordlists

  • /usr/share/wordlists/rockyou.txt — most common password wordlist (comes with Kali, may need to be unzipped first)
  • SecLists — large repository of wordlists for usernames, passwords, and fuzzing payloads
  • crunch — tool to generate custom wordlists based on patterns/character sets
  • cewl — scrapes a target website to build a context-aware custom wordlist
# Unzip rockyou.txt if compressedsudo gunzip /usr/share/wordlists/rockyou.txt.gz

9. Timing, Throttling & Reliability Options

FlagDescription
-tNumber of parallel connections/tasks (default 16). Lower this against fragile or rate-limited services
-wMax wait time (seconds) for a response per attempt
-WWait time between connects
-cPause (seconds) between each login attempt per thread — helps evade lockouts/IDS
-IIgnore an existing restore file and start a fresh scan
-RRestore a previously interrupted session
# Resume a previously interrupted Hydra scanhydra -R

10. Output & Logging Options

FlagDescription
-o <file>Write found credentials to a file
-b <format>Output format: text, json, jsonv1
-fExit after the first valid login/password pair is found (single target)
-FExit after first valid pair is found on ANY target (multi-target scans)
-dDebug mode — extra diagnostic output
-qSuppress connection error messages
# Save results in JSON format and stop at first hithydra -l admin -P rockyou.txt MACHINE_IP -f -o results.json -b jsonv1 ssh

15. HTTPS Forms & SSL Considerations

For login forms served over HTTPS, use https-post-form (or https-get-form) instead of the plain HTTP module:

# Same attack as before, but over HTTPShydra -l admin -P rockyou.txt MACHINE_IP https-post-form "/login:username=^USER^&password=^PASS^:F=incorrect"
Add extra -V/-d flags when debugging why a form-based attack isn't detecting failures correctly — an incorrect F= string is the most common cause of false "0 valid passwords" results.

16. Identifying the Correct Failure/Success String

Getting the F= (failure string) or S= (success string) wrong is the #1 reason Hydra reports "0 valid passwords found" even when a correct password exists. To find the right string:

  1. Open the login page in a browser with developer tools (Network tab) open.
  2. Submit one deliberately wrong login and inspect the response body/headers.
  3. Submit one known-correct login and compare the response.
  4. Pick a string that appears only on failure (use F=) or only on success (use S=) — e.g. a redirect header, cookie, or specific error text.

18. Defensive Measures Against Brute-Force Attacks (Blue Team Notes)

  • Account lockout policies after N failed attempts
  • Rate limiting / throttling on login endpoints
  • Fail2ban or similar IPS to auto-block offending IPs
  • Multi-factor authentication (MFA) to neutralize password-only brute forcing
  • CAPTCHA on web login forms after repeated failures
  • Strong password policies, banning common/breached passwords
  • Monitoring & alerting on abnormal authentication volume (SIEM rules)
  • Disabling unused/legacy protocols (e.g., Telnet, FTP) in favor of encrypted alternatives

19. Ethical & Legal Reminder

⚠️ Only run Hydra against systems you own, or for which you have explicit, documented, written authorization (e.g., a signed penetration testing engagement or a lab environment like HackTheBox/TryHackMe). Unauthorized brute-forcing of login systems is illegal in most jurisdictions under computer misuse / unauthorized access laws.
